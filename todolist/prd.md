## 1. 개요

### 1.1 배경
하루 단위로 해야 할 일을 빠르게 적고, 완료 여부를 체크하며, 오늘의 진행 상황을 한눈에 확인할 수 있는 가벼운 웹페이지가 필요하다. 설치나 로그인 없이 브라우저만으로 바로 쓸 수 있어야 한다.

### 1.2 목표
- 오늘 할 일을 **3초 안에** 추가할 수 있다.
- 완료/미완료 상태와 진행률을 한눈에 확인할 수 있다.
- 새로고침하거나 브라우저를 닫았다 열어도 데이터가 유지된다.
- 별도 서버·빌드 도구 없이 정적 파일만으로 동작한다.

### 1.3 비목표 (이번 범위에서 제외)
- 회원가입/로그인, 다중 사용자, 기기 간 동기화
- 서버/DB 연동
- 알림(푸시), 반복 일정, 캘린더 연동
- 협업(공유, 댓글)

## 2. 대상 사용자 & 사용 시나리오

**대상 사용자:** 하루 업무·개인 일정을 간단히 관리하고 싶은 개인 사용자

**시나리오**
1. 아침에 페이지를 열고 오늘 할 일 5개를 연속으로 입력한다.
2. 일을 마칠 때마다 체크박스를 눌러 완료 처리한다. 진행률 바가 올라간다.
3. 잘못 적은 항목은 더블클릭해 수정하고, 필요 없는 항목은 삭제한다.
4. 오후에 "남은 일" 필터로 미완료 항목만 본다.
5. 다음 날 페이지를 열면 어제 끝내지 못한 일이 "어제에서 넘어온 일"로 표시되어, 오늘로 가져올지 선택한다.

## 3. 기능 요구사항

우선순위: **P0** = MVP 필수, **P1** = MVP 이후 우선, **P2** = 선택

### 3.1 할일 관리 (P0)
| ID | 기능 | 상세 |
|---|---|---|
| F-01 | 할일 추가 | 입력창에 텍스트 입력 후 Enter 또는 "추가" 버튼. 앞뒤 공백 제거, 빈 값은 추가 불가. 최대 100자. 추가 후 입력창 포커스 유지 |
| F-02 | 완료 토글 | 체크박스 클릭으로 완료/미완료 전환. 완료 항목은 취소선 + 흐린 색 |
| F-03 | 할일 수정 | 텍스트 더블클릭(모바일: 수정 버튼) → 인라인 편집. Enter 저장, Esc 취소, 빈 값 저장 시 기존 값 유지 |
| F-04 | 할일 삭제 | 항목 hover 시 삭제 버튼 노출(모바일은 항상 노출). 클릭 즉시 삭제 + 5초간 "실행 취소" 토스트 |
| F-05 | 데이터 유지 | 모든 변경은 즉시 localStorage에 저장 |

### 3.2 오늘 화면 (P0)
| ID | 기능 | 상세 |
|---|---|---|
| F-06 | 오늘 날짜 표시 | 상단에 `2026년 11월 2일 (월)` 형식으로 표시 |
| F-07 | 진행률 | `완료 3 / 전체 5` 텍스트 + 진행률 바(%) |
| F-08 | 필터 | 전체 / 남은 일 / 완료 탭 |
| F-09 | 완료 항목 일괄 삭제 | "완료 항목 지우기" 버튼 (완료 항목이 있을 때만 활성) |
| F-10 | 빈 상태 | 할일이 없으면 안내 문구 표시 ("오늘 할 일을 추가해 보세요") |

### 3.3 부가 기능 (P1)
| ID | 기능 | 상세 |
|---|---|---|
| F-11 | 미완료 이월 | 날짜가 바뀐 뒤 접속 시, 이전 날짜의 미완료 항목을 배너로 안내 → "오늘로 가져오기" / "무시" |
| F-12 | 우선순위 | 항목별 중요 표시(★). 중요 항목은 목록 상단 정렬 |
| F-13 | 순서 변경 | 드래그 앤 드롭으로 순서 변경 |
| F-14 | 다크 모드 | 시스템 설정 따름 + 수동 토글 |

### 3.4 선택 기능 (P2)
- F-15 지난 날짜 기록 보기(날짜 이동 ◀ ▶)
- F-16 모두 완료 시 축하 애니메이션
- F-17 JSON 내보내기/가져오기 (백업)

### 4.2 반응형
- 최대 너비 560px, 가운데 정렬
- 모바일(≤ 480px): 좌우 여백 16px, 편집·삭제 버튼 항상 노출, 터치 영역 최소 44×44px

### 4.3 디자인 가이드
- 색상은 CSS 변수(`--bg`, `--text`, `--accent`, `--muted`, `--done`)로 정의하고 다크 모드에서 재정의
- 폰트: 시스템 폰트 스택 (`Pretendard`가 있으면 우선)
- 애니메이션: 항목 추가/삭제 시 150ms 페이드, `prefers-reduced-motion` 시 비활성

## 5. 데이터 설계

### 5.1 데이터 모델
```ts
interface Todo {
  id: string;          // crypto.randomUUID()
  text: string;        // 1~100자
  done: boolean;
  important: boolean;  // P1
  date: string;        // 'YYYY-MM-DD' (로컬 시간 기준, 이 할일이 속한 날짜)
  order: number;       // 정렬 순서 (P1 드래그용)
  createdAt: number;   // epoch ms
  completedAt: number | null;
}

interface AppState {
  version: 1;          // 스키마 버전 (마이그레이션 대비)
  todos: Todo[];
  settings: {
    theme: 'system' | 'light' | 'dark';
    lastVisitDate: string; // 'YYYY-MM-DD', 이월 판단용
  };
}
```

### 5.2 저장소
- `localStorage` 키: `todolist:v1`
- 값: `AppState`를 JSON 직렬화
- 읽기/쓰기는 `try/catch`로 감싸고, 실패(용량 초과, 시크릿 모드 등) 시 메모리 상태로 계속 동작 + 경고 토스트
- 파싱 실패 시 손상 데이터를 `todolist:v1:backup`으로 옮기고 빈 상태로 시작

### 5.3 날짜 처리
- "오늘"은 사용자 로컬 시간 기준 `YYYY-MM-DD`
- 페이지가 자정을 넘겨 열려 있는 경우를 대비해, `visibilitychange`(탭 복귀) 시 날짜를 다시 계산

## 6. 기술 설계

### 6.1 기술 스택
- **HTML + CSS + Vanilla JavaScript (ES Modules)**
- 프레임워크·빌드 도구·외부 의존성 없음 → `index.html`을 브라우저로 열면 바로 동작
  - 단, ES Modules는 `file://`에서 제한될 수 있으므로 로컬 확인은 간단한 정적 서버(`npx serve` 등) 사용을 권장

### 6.2 폴더 구조 (예정)
```
todolist/
├── prd.md            # 본 문서
├── index.html        # 마크업
├── css/
│   └── style.css     # 스타일, CSS 변수, 다크 모드
└── js/
    ├── main.js       # 진입점: 초기화, 이벤트 바인딩
    ├── store.js      # 상태 관리 + localStorage 입출력
    ├── todo.js       # 할일 CRUD 순수 함수
    ├── render.js     # DOM 렌더링
    └── date.js       # 날짜 유틸 (오늘 키, 표시 포맷)
```

### 6.3 아키텍처
단방향 데이터 흐름으로 단순하게 유지한다.

```
사용자 이벤트 → main.js(핸들러) → store.dispatch(action)
                                      │
                         todo.js 순수 함수로 새 상태 계산
                                      │
                       localStorage 저장 → render(state)
```

- **store.js**: `getState()`, `dispatch(action)`, `subscribe(listener)` 제공
- **액션 목록**: `ADD`, `TOGGLE`, `EDIT`, `DELETE`, `RESTORE`(실행 취소), `CLEAR_DONE`, `SET_FILTER`, `TOGGLE_IMPORTANT`, `REORDER`, `CARRY_OVER`, `SET_THEME`
- **render.js**: 상태 전체를 받아 목록을 다시 그림 (항목 수가 적으므로 가상 DOM 불필요). 이벤트는 목록 컨테이너에 위임(event delegation)
- 필터 상태는 저장하지 않고 URL 해시(`#/active`, `#/done`)로 관리 → 새로고침 시에도 유지

### 6.4 보안
- 사용자 입력은 `textContent`로만 렌더링 (`innerHTML` 사용 금지) → XSS 방지

## 7. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 성능 | 첫 로드 1초 이내, 할일 500개에서도 조작 지연 체감 없음 |

## 8. 예외 처리

| 상황 | 처리 |
|---|---|
| 빈 문자열 / 공백만 입력 | 추가하지 않고 입력창 흔들림 + 안내 |
| 100자 초과 | 입력 제한(`maxlength`) + 남은 글자 수 표시 |
| localStorage 사용 불가 | 메모리 모드로 동작, "저장되지 않습니다" 배너 |
| 저장 데이터 손상 | 백업 키로 이동 후 초기화, 안내 토스트 |
| 자정 경과 | 탭 복귀 시 날짜 재계산 → 이월 배너 표시 |
